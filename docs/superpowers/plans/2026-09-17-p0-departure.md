# P0 出发闭环实施计划

目标：让导航、地点及预约确认、首尾交通与时间冲突检查形成闭环。原域名发布，无收费服务和服务端密钥。

实现：departure.js 负责地图链接、日期范围内的场次/预约数据合并与出发检查；departure-ui.js 负责核实表单和清单；planner.js 处理缺失交通、出发及返程时间、固定场次，planner-ui.js 展示完整时间轴。现有 localStorage 数据向后兼容。

- [x] 先为地图编码、活动季具体场次、预约失效、出返程超时、未核实交通写测试并观察失败。
- [x] 实现高德地点搜索、百度按名称双点路线。百度 Web URI 仅支持公交/驾车/步行，骑行跳高德搜索并明确须在地图选骑行和起点。地图中心坐标仅用于估算，不冒充场馆入口。
- [x] 添加当天入口确认、开放确认、预约状态与参观时段；不可预约/关闭不排入。活动季须填具体场次、场地和固定时间。未知坐标间路程必须手动补充。
- [x] 添加可选出发地与返程地、出发时间及最晚返回，边界交通和缓冲计入总时间。新增逐段核实表单；修改日期/交通/地点清除失效核实。
- [x] 出发检查显示未安排站点、未知开放/预约/入口、估算交通、缺少首尾路程；资料来源与用户确认分开标识。
- [x] 运行 node --test tests/*.test.cjs，验证浏览器桌面/手机、保存、日期切换、地图链接和错误恢复；原域名发布并比对静态资源。

资料：https://developer.amap.com/api/uri-api/guide/search/search 与 https://lbs.baidu.com/docs/webapi?title=mapadjustment/uri/web 。路线查询为跳转，非后台导航 API；地图中的实际时间需用户回填，绝不宣称实时交通已接入。
